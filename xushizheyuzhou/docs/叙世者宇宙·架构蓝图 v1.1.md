# 叙世者宇宙 · 门户架构蓝图 v1.1

> 一次对话,打开一个世界。
> 叙 = 一颗颗各自的故事;世 = 故事聚成的世界;者 = 讲述、编织与见证的我们。

本蓝图定义叙世者宇宙的世界观映射、信息架构、页面层级、数据结构、权限边界与建设路线,作为后续所有开发与内容工作的总纲。渲染层视觉规范已另行锁版,不在本文档重复。

v1.1 修订要点:恢复"一对新人 = 一颗星"的初衷(回访以光环表达,不再另立星球);场地升格为星云,按城市聚成星域带,自身可点击;合作伙伴(主持、摄影、摄像等)以彗星形态入宇宙,与新人、场地共存于同一页面。

---

## 一、产品定位

叙世者宇宙是一个三位一体的站点:对外,它是公司官网与年度作品集(「叙世者 20XX 星图」),访客进入即见宇宙;对客户,它是每对新人的专属档案馆,凭专属入口回访自己的星;对内,它是全部案例、场地与伙伴资源的可视化资料库——客户在同一个宇宙里看新人的故事、看场地的沉淀、看伙伴的作品,选择时一目了然。

核心体验只有一句话:**每一段被我们见证的感情,都是这个宇宙里一颗真实存在、可以走进去的星;而孕育它们的场地、陪伴它们的伙伴,也都在这片天空里。**

---

## 二、宇宙的居民:实体模型

宇宙里可见的天体有三种,加上不可见的组织概念,共六类实体。

**星(System)= 一对新人。宇宙的主角。** 一对新人在宇宙里永远只有一颗星,落在他们第一段故事的年份圈上。他们名下可以有多段故事(婚礼、纪念日、宝宝宴……),每多一段,星的外围便多一道细金光环——远看,戴光环的星就是"回来过的人"。星的颜色由录入时填写的主辅色生成,大小与资料丰富度相关,核心亮度由状态决定(已成篇点亮、进行中微光)。

**故事(Story)= 星内的世界。** 每段故事是一颗独立的"故事星球",装着自己的五域(场地 / 故事 / 流程 / 视觉 / 那一刻),彼此绝不混淆。只有一段故事的星,点击直达五域;多段故事的星,进入后先见并肩的故事星球(如"婚礼·2026 / 纪念日·2028"),择一而入。

**星云(Venue)= 场地。恒星诞生之地。** 天文学的事实即是我们的隐喻:恒星在星云中诞生,新人的星在场地里点亮。每个场地是一朵星云,按城市聚成星域(杭州星域、上海星域……),分布在年轮星图外围的星域带上。点击星云本身即打开场地档案(简介、影像、我们在此的设计沉淀、在此诞生的所有星);悬停星云,诞生于此的星一齐亮起。单城市可容纳数十朵星云,支持搜索与按城市筛选。

**彗星(Partner)= 合作伙伴。穿行于星系之间的旅人。** 主持人、摄影师、摄像师、乐手……他们不属于哪一颗星,却在无数故事里留下划痕。每位伙伴是一颗彗星,沿平缓的轨迹在年轮星图与星域带之间的环隙缓慢巡游(慢到可以从容点击),拖着微弱的尾迹。点击彗星打开伙伴档案(简介、角色、参与过的故事);悬停彗星,他服务过的星一齐亮起——客户选摄影师,就是看他点亮过哪些星。伙伴同时有集中索引页,方便按角色浏览。

**标签(Tags)= 风格与元素。** 星空、自然野趣、手写信、星石……挂在故事上,驱动搜索、筛选与缘分表达。

**年轮(Year Ring)= 年份圈。** 宇宙的时间结构,一圈一年,最早年份在最内,宇宙随故事向外生长。年度星图是策展页,按故事发生年份收录,不受星位约束。

### 关系速览

一颗星拥有 1..n 段故事;每段故事诞生于一朵星云、由若干彗星陪伴、携带标签、属于一个年份。悬停任何天体,与之相关的天体亮起:星→它的星云与彗星;星云→在此诞生的星;彗星→他陪伴过的星。连线只在悬停时浮现,作氛围而非入口——**入口永远是天体本身**。

### 宇宙分区

由内向外:年轮星图(新人的星)→ 环隙彗星带(伙伴巡游)→ 星域带(城市星云群)。三层各司其职,互不侵占;深空背景星尘贯穿全域。

## 三、页面层级与导航

**L0 · 宇宙全景。** 进入即见三层分区。底部年份导航(发光圆点),顶部搜索(新人 / 场地 / 伙伴 / 风格通搜)与筛选(年份、城市、伙伴角色),闲置巡航环游,背景程序化音乐。悬停任何天体:轻微放大 + 名字牌 + 关联天体亮起。

**L1 · 选中与进入(星)。** 单击星,镜头连贯滑送至画面中心,停顿蓄势,爆裂转场,进入星内——一次点击完成。飞行途中 ESC 或点空白取消。

**L2 · 星内世界。** 单故事:直达该故事的五域小星系(平级环列,整体旋转,主色染场)。多故事:先见故事星球并肩(各带光环年份牌),择一进入其五域。页内提供成篇入口、方案入口(私密)、场地星云入口、伙伴署名入口、返回宇宙。

**L3 · 域内容。** 各域具体形态在内容设计阶段定义,原则:轻覆层,不离开星内场景,关闭即回 L2。流程域与视觉域中的伙伴署名可点,跳转伙伴档案。

**档案页(覆层形式)。** 场地档案:由星云或故事的场地域进入;伙伴档案:由彗星、故事署名或伙伴索引进入。两者同版式:简介、影像 / 沉淀、关联的星(点击可飞往)。

**独立页面。** 年度星图页(某一年的策展合集,可对应实体印刷星图);编织者与伙伴索引;关于叙世者。

## 五、权限与公开边界

三级可见性:**访客**见宇宙全貌与所有公开层——星的公开信息、场地档案、伙伴档案均公开,可点亮;**新人**凭专属链接或口令进入自己的星,见私密层全部内容(五域、成篇、方案);**团队**见一切并可编辑。私密内容默认不进入任何公开页面的渲染与搜索索引。新人真名默认不公开,公开名可为化名或姓氏格式,由录入时选择。伙伴与场地档案默认公开,单条可设隐藏。

---

## 六、点亮机制

访客可为喜欢的星点亮;点亮数以温和系数(1.0~1.3)驱动该星浓彩环与核心亮度,宇宙因被喜爱而更亮。上线初期只做最简防刷(同设备限一次),不过度设计。

---

## 七、技术架构备忘

渲染:锁版点彩贴图工厂(2048px 基准 / 聚焦 4096px 重生成,同 seed)+ three.js 三层视线轴对齐 Sprite + 发光星球本体;星云复用点彩工厂的低密度大尺寸配方(无核、更弥散),彗星 = 小发光体 + 短粒子尾迹;粒子永远哑光,泛光只服务发光本体。相机:统一阻尼追赶系统,巡航锚定星图中心,一切运动一条曲线,禁止终点硬赋值。转场:爆裂粒子取该案主辅色。音乐:WebAudio 程序化氛围,进入星内时可随主色微调音色(远期)。录入:后台表单按第四节 schema 收敛,主辅色为取色器字段。

## 八、建设路线

**P0 已完成:** 点彩渲染定稿并锁版;3D 底盘嫁接;暖金气质统一;年轮布局;发光星球本体;两级场景与爆裂转场骨架。

**P1 进行中:** 巡航锚定、单击连贯进入、五域小星系形态(平级整体旋转)。

**P2 数据换血与宇宙扩容:** 按本蓝图 schema 重建数据层(systems / stories / venues / partners 四集合、公私分层、反向引用构建脚本);星位改由 system 首段故事决定,光环表达回访;星域带与星云渲染、彗星带与彗星渲染;悬停关联点亮;场地与伙伴档案覆层页;假数据按新模型重写(含 6~8 朵星云、4~6 颗彗星)。

**P3 内容与形态:** 五域各自的 L3 内容形态设计;多故事星的故事星球选择视图;成篇阅读页;年度星图页;伙伴索引页。

**P4 上线准备:** 权限与专属链接;点亮;录入后台;移动端适配;部署与域名;远期增强(星域视图切换:全部星按场地重新聚拢)。
